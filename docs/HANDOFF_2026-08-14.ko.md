## 2. 구현된 범위

### ArmGS 모델 및 학습 경로

- background Gaussian의 local appearance refinement
- image-wise global appearance refinement
- dynamic actor Gaussian refinement
- actor class embedding, class encoder, class-wise hash-grid 경로
- background와 actor를 같은 depth ordering으로 rasterize하는 composite renderer
- sky 합성과 global affine refinement
- RGB, expected depth, actor alpha 출력을 사용하는 학습 loss
- LiDAR depth, sky/actor mask supervision
- PSNR, SSIM, LPIPS-Alex 평가와 W&B 로깅
- 기본 렌더 이미지 로깅 간격 500 step

### 데이터와 초기화

- nuScenes scene 0061 학습 및 Grounded SAM sky-mask 생성 경로
- Waymo v2 FRONT 카메라 로더와 scene cache
- Waymo LiDAR point initialization
- known-pose COLMAP triangulation 결과를 추가 initialization point로 병합
- 동적 actor cuboid/track 로딩과 actor Gaussian 초기화
- Grounded SAM sky mask 생성 및 검증
- W&B sidecar를 이용한 run identity와 resume 검증

주의: 현재 COLMAP 경로는 카메라 pose를 새로 추정하는 일반적인 unconstrained SfM이 아니라, Waymo의 알려진 pose를 고정한 known-pose triangulation이다.

## 3. Waymo split 구현

두 프로토콜을 분리해서 지원한다.

1. `streetgs-periodic`
   - FRONT capture 위치 `4, 8, 12, ...`를 holdout으로 사용한다.
   - 기존 `splatad_30k` 실험이 실제로 사용한 split이다.
   - 기본 LiDAR initialization은 `all-selected`이다.

2. `linspace`
   - SplatAD의 per-sensor 50% 규칙을 재현한다.
   - `ceil(N * 0.5)`개 위치를 `numpy.linspace(0, N-1, ..., dtype=int64)`로 선택한다.
   - 나머지 capture를 evaluation set으로 사용한다.
   - LiDAR와 known-pose COLMAP 모두 training capture만 사용한다.
   - split provenance를 `mapping.json`, runtime metadata와 checkpoint identity에 저장하고 정확히 검증한다.

SplatAD LINSPACE50 전용 실행기는 다음 namespace를 사용해 기존 실험과 섞이지 않게 한다.

- launcher: `scripts/train_armgs_waymo_splatad_linspace50_batch.sh`
- COLMAP: `data/waymo_prepared/colmap_splatad_linspace50/<sequence>`
- output: `outputs/waymo/<sequence>/splatad_linspace50_30k`
- W&B run prefix: `armgs_waymo_splatad_linspace50`

실행 예시는 다음과 같다.

```bash
GPU_IDS=0,1 \
WANDB_ENTITY=CamoSplat_ICLR_2027 \
WANDB_PROJECT=Ours-ArmGS-Waymo \
scripts/train_armgs_waymo_splatad_linspace50_batch.sh
```

한 scene만 점검하려면 다음처럼 실행한다.

```bash
GPU_IDS=7,6 \
scripts/train_armgs_waymo_splatad_linspace50_batch.sh \
  --only 4986495627634617319_2980_000_3000_000
```

## 5. 검증 및 체크포인트 제약

최신 LINSPACE 변경의 핵심 테스트는 다음과 같다.

```bash
CUDA_VISIBLE_DEVICES='' /venv/camosplat/bin/python -m pytest -q \
  tests/test_data_split.py \
  tests/test_prepare_waymo_colmap.py \
  tests/test_training_cli_waymo.py
```

2026-08-14 실행 결과: `70 passed in 1.92s`.

Waymo trainer는 현재 `checkpoint_callback=None`으로 실행되며 학습 종료 후 `checkpoints/final.pt`만 저장한다. CLI의 `--checkpoint-interval` 값이 있어도 중간 checkpoint가 생기지 않는다. 따라서 프로세스가 중단되면 마지막 step부터 resume할 수 없고 처음부터 다시 실행해야 한다. 이 부분은 다음 우선순위 수정 사항이다.

## 6. 논문/공식 수치 재현 시 남은 차이와 위험

- 기존 `splatad_30k` 결과는 SplatAD LINSPACE50 split이 아니다. 새 전용 launcher로 다시 측정해야 한다.
- actor tracking은 공식 StreetGS CAStrack 파일이 없으면 Waymo GT box fallback을 사용한다. 이 경우 tracker parity를 주장할 수 없다.
- COLMAP initialization은 known-pose triangulation이며 일반적인 pose-estimating SfM과 다르다.
- pure-PyTorch hash-grid와 다수 actor Gaussian은 scene에 따라 CUDA reserved memory가 48 GiB 수준까지 증가한다.
- 이동 전 절대경로가 들어간 오래된 checkpoint/mapping metadata는 strict resume/eval identity 검사에서 충돌할 수 있다. 새 실험은 현재 저장소 경로에서 fresh preparation하는 것이 안전하다.
- 논문 수치 비교 전 SH backend parity, composite single-depth-order synthetic test, 전체 backward/gradient test를 다시 확인하는 것이 좋다.

## 7. 다음 작업 권장 순서

1. 실행 중인 `756669...`가 30k와 final evaluation까지 완료됐는지 확인한다.
2. Waymo 중간 checkpoint callback을 연결하고 resume 회귀 테스트를 추가한다.
3. `scripts/train_armgs_waymo_splatad_linspace50_batch.sh --dry-run`으로 namespace와 split을 재확인한다.
4. LINSPACE50용 COLMAP을 새로 준비하고 10개 scene을 학습한다.
5. 각 scene의 novel-view PSNR/SSIM/LPIPS-Alex를 집계해 공식 설정과 비교한다.
6. 공식 CAStrack 입력을 확보하면 Waymo GT fallback 실험과 분리해 다시 평가한다.
